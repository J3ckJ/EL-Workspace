# История изменений

Проект придерживается [Semantic Versioning](https://semver.org/lang/ru/) и
формата [Keep a Changelog](https://keepachangelog.com/ru/1.1.0/).

## [Unreleased]

### Добавлено

- локальный Git-хост `el serve`: bare-репозитории, smart HTTP и SSH через
  системный `git upload-pack` / `receive-pack`, веб-интерфейс в духе EL Midnight;
- обзор репозиториев, поиск по коду, коммитам и задачам, история и diff
  (единый и раздельный вид, клавиши J/K);
- pull request с комментариями к строкам, предложенными правками и слиянием
  merge / squash / rebase;
- доска задач по всем репозиториям и автозакрытие по `fixes #N` при слиянии в
  основную ветку;
- релизы из CHANGELOG и коммитов с прошлого тега, файлы со SHA-256, публикация
  тега на зеркало и `el release <tag> --from-ci`;
- локальный запуск `.github/workflows` (шаги `run` и `actions/checkout`) на
  машине, где работает сервер;
- зеркало GitHub: push при слиянии, очередь на время офлайна, force-push только
  после подтверждения списка коммитов, которые будут потеряны;
- ночной `git bundle` и раздел SSH-ключей;
- панель `#/panel`, скрипт меню-бара macOS и трей Windows;
- команды `el pr checkout` и `el serve` в лаунчере PowerShell;
- светлая тема рядом с EL Midnight, пустые экраны, недоступный сервер,
  офлайн-очередь и конфликт зеркала;
- движение интерфейса: тост сборки и зеркала, очередь пакетов, свёртка
  ревью, открытие панели. Длительности совпадают с токенами v3.

### Изменено

- лаунчер проектов не меняет поведение `el`, `el <проект>` и `el run`; новые
  команды хоста уходят в отдельный бинарник.

## [0.1.2] — 2026-07-31

### Исправлено

- установка и `el-project sync` больше не требуют, чтобы каждый сохранённый
  диск проекта был подключён прямо сейчас; офлайн-проект остаётся в реестре и
  Terminal fragment, а доступность проверяется при открытии/диагностике;
- lifecycle test включает проект на отсутствующем диске и проверяет сохранение
  его `startingDirectory` без обращения к PowerShell drive provider.

## [0.1.1] — 2026-07-31

### Исправлено

- one-line установка `irm ... | iex` больше не конфликтует с валидацией
  необязательного `SourceSha256`; формат SHA-256 по-прежнему проверяется до
  работы с локальным ZIP;
- regression suite теперь отдельно воспроизводит PowerShell binding bootstrap
  через pipeline, то есть именно публичный сценарий установки.

## [0.1.0] — 2026-07-31

### Добавлено

- транзакционная установка EL Workspace для текущего пользователя из GitHub
  Release с backup и автоматическим rollback;
- release-архив и checksum manifest SHA-256 с проверкой путей ZIP до
  распаковки;
- сохранение реестра проектов и состояния launcher при обновлении;
- структурное объединение темы с существующими настройками Windows Terminal;
- необязательная user-space установка zoxide, fzf, Oh My Posh и Nerd Font;
- launcher `el` и менеджер проектов `el-project`;
- безопасное распознавание PWA, Docker Compose, Node.js, Python, .NET, Rust,
  Go и generic-проектов;
- подтверждаемый `.el-project.json` с локальным snapshot задач;
- рабочие пространства и палитра команд Windows Terminal;
- контекстные заголовки, цвета вкладок и индикатор выполнения задач;
- быстрый выбор проектов `elj`, интеграции `zoxide` и `fzf`;
- короткие команды `app`, `clean`, `site`, `serve`, `g`, `publish` и
  `update-tools`;
- команды `doctor`, `update`, `backup`, `restore` и безопасное удаление;
- изолированные smoke-тесты установки и сборка release-артефактов с SHA-256.

### Безопасность

- project manifest не исполняется как произвольная командная строка;
- пути задач ограничены каталогом проекта, а опасные автоматические задачи
  исключены;
- профиль PowerShell изменяется только внутри маркированного блока;
- повреждённый либо неоднозначный managed profile block отклоняется;
- восстановление проверяет inventory и SHA-256 каждого файла;
- install, backup, restore и uninstall отказываются работать через reparse
  components;
- удаление ограничено каталогами EL Workspace и требует подтверждения.
